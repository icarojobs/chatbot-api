# RFC-0004 — Hospedagem na Vercel (substitui o Cloud Run)

- **Status:** Aprovada
- **Data:** 28/10/2026
- **Autor:** icarojobs

## Contexto

O plano original (RFC-0002, ADR-0005) era publicar a API no Google Cloud Run com o banco no Neon. A conta de faturamento do Google Cloud foi bloqueada ("not in good standing") e o Cloud Run não funciona sem faturamento ativo. O Neon (plano gratuito, sem cartão) já está criado. Era preciso outra hospedagem gratuita, sem cartão, com SSE e de preferência perto do Neon (AWS São Paulo).

## Decisões

| # | Questão | Opções | Decisão |
|---|---|---|---|
| 1 | Plataforma | Vercel · Render free · Hugging Face Spaces | **Vercel (Hobby)**: grátis sem cartão, região São Paulo (`gru1`), FastAPI e streaming nativos |
| 2 | Runtime | Python nativo · Container (Dockerfile, beta) | **Python nativo** (GA): módulo `chatbot_api.asgi` com `app` no nível do módulo |
| 3 | Deploy automático | Integração Git só na `main` · GitHub Actions + Vercel CLI | **Integração Git só na `main`**, previews desligados (`git.deploymentEnabled`) |
| 4 | Upload direto acima de 4,5 MB | Limitar a 4 MiB · Manter 30 MiB | **4 MiB em produção** (`DIRECT_UPLOAD_MAX_BYTES`); arquivos maiores usam o upload em partes |

## Justificativas

- **Render** já tinha sido descartado (suspensão com cold start de ~1 min, sem região na América do Sul). **Hugging Face Spaces** não foi feito para APIs e também suspende.
- **Python nativo** é estável e tem cold start menor que o runtime de containers, que ainda está em beta. A imagem Docker continua sendo usada no ambiente local.
- **Só a `main` publica:** a `main` já exige os 6 checks; previews de PR usariam o banco de produção e gastariam créditos do provedor.
- **Upload em partes:** cada parte tem 4 MiB, abaixo do limite de 4,5 MB por requisição; nada muda para PDFs grandes.
