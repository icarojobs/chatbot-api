# RFC-0005 — Página de upload que divide o arquivo automaticamente

- **Status:** Aprovada
- **Data:** 29/10/2026
- **Autor:** icarojobs

## Contexto

Na Vercel, cada requisição tem no máximo 4,5 MB (ADR-0010), e as apostilas têm de 5,6 a 16 MB. Em produção elas só entram pelo upload em partes, que exige calcular o SHA-256, dividir o arquivo em partes de 4 MiB e enviar cada parte. Pelo Swagger ou pelo Postman, isso é manual e trabalhoso para quem avalia a API.

O servidor não pode receber o arquivo inteiro e dividi-lo: a Vercel recusa a requisição antes de ela chegar à API. A divisão precisa acontecer em quem envia.

## Decisões

| # | Questão | Opções | Decisão |
|---|---|---|---|
| 1 | Cliente que divide o arquivo | Página `/upload` servida pela API · HTML local em `docs/` · `make upload-prod` · Vercel Blob | **Página `/upload` na API**: abrir a URL, informar o token admin, escolher um PDF e enviar |
| 2 | Comando de terminal complementar | Só a página · Página + `make upload-prod` | **Só a página** |

## Justificativas

- **Página na API:** quem avalia não precisa do repositório nem de ferramentas; a página usa os mesmos endpoints públicos (`/v1/documents/uploads`), então o contrato da API não muda e o Swagger continua igual.
- O navegador calcula o SHA-256 (Web Crypto), divide o arquivo com `Blob.slice`, envia só as partes que ainda não chegaram (`received_parts`), conclui e acompanha o documento até `ready`.
- **Vercel Blob** descartado: adicionaria um serviço e infraestrutura, e ainda exigiria um cliente JavaScript.

## Consequências

- `GET /upload` não exige token (é só HTML); as chamadas feitas pela página exigem o token admin, digitado na página e nunca guardado.
- A página é servida com Content-Security-Policy restrita (scripts e estilos autorizados por hash, conexões só para a própria origem), sem `unsafe-inline`.
- O rate limit global também vale para `/upload`.
