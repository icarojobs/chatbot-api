# ADR-0001 — Stack, layout do projeto e fundação da API

- **Status:** Aceito
- **Data:** 27/10/2026
- **Contexto de decisão:** [RFC-0002](../RFC/RFC-0002.md), Fase 1 do [plano](../planejamento/PLANO_DE_DESENVOLVIMENTO.md)

## Contexto

A API precisa de uma base que trate configuração, autenticação, rate limiting, erros e logs de forma uniforme antes de qualquer regra de negócio, e que suporte streaming SSE (Fase 6) sem buffering.

## Decisões

1. **Python 3.14.x + uv 0.13.6** (`requires-python ==3.14.*`, `required-version` do uv fixado), com dependências pinadas com `==` e o `uv.lock` versionado. O 3.15 foi descartado por risco de falta de wheels em libs nativas.
2. **Layout `src/chatbot_api/`** com `core/` (config, erros, segurança, rate limit, logs) e `api/routes/`. A app é criada por *factory* (`create_app(settings)`), executada com `uvicorn --factory`: os testes injetam `Settings` sem depender de `.env`.
3. **Configuração com `pydantic-settings`** (imutável e validada no startup); tokens são `SecretStr` com no mínimo 32 caracteres. As listas de modelos aceitam o formato do `.env` existente (`"a,b"`).
4. **Erros no formato da OpenAI** (`{"error": {"message", "type", "param", "code"}}`) para todas as respostas de erro, inclusive 404, 422 (convertido em 400, como a OpenAI) e 500 (mensagem genérica, sem detalhes internos).
5. **Autenticação Bearer** com dois tokens (`API_ACCESS_TOKEN` para consumo e `API_ADMIN_TOKEN` para administração), comparados com `hmac.compare_digest` (tempo constante).
6. **Rate limiting com middleware ASGI próprio sobre a lib `limits`** (janela móvel em memória), aplicado a todas as rotas, com `Retry-After` no 429.
7. **Logs JSON com `structlog`** e `x-request-id` (aceito do cliente se válido, senão gerado), via middleware ASGI puro.
8. **Docker multi-stage** (imagens fixadas por digest, usuário não-root, healthcheck) e `docker compose` com API, PostgreSQL + pgvector e Ollama (CPU por padrão; GPU via `docker-compose.gpu.yml`).

## Alternativas consideradas

- **slowapi** (planejada inicialmente): descartada após testes. O limite global via middleware não foi aplicado, e o middleware ASGI dela segura o `http.response.start` e o reenvia a cada chunk do corpo, o que quebraria o streaming SSE. O middleware próprio tem ~60 linhas, rejeita antes de executar a rota e nunca toca no corpo da resposta.
- **`--proxy-headers` do uvicorn** para obter o IP real: com `--forwarded-allow-ips='*'` o uvicorn usa a entrada mais à esquerda do `X-Forwarded-For`, que é controlada pelo cliente — permitiria burlar o rate limit. Optou-se por `TRUSTED_PROXY_HOPS`: usa-se apenas a entrada adicionada pelo proxy confiável (Cloud Run = 1).

## Consequências

- O rate limit é por instância (memória do processo). Com várias instâncias no Cloud Run o limite efetivo se multiplica; aceitável no escopo atual. Se necessário, a lib `limits` suporta Redis trocando só o storage.
- Tokens estáticos não têm revogação por usuário; a troca exige atualizar o segredo e reiniciar.
- O Ollama em container roda em CPU nesta máquina (sem NVIDIA Container Toolkit), o que é suficiente para desenvolvimento.
