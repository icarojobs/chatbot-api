# ADR-0003 — PostgreSQL + pgvector e pipeline de ingestão

- **Status:** Aceito
- **Data:** 27/10/2026
- **Contexto de decisão:** [RFC-0002](../RFC/RFC-0002.md), Fase 3 do [plano](../planejamento/PLANO_DE_DESENVOLVIMENTO.md)

## Contexto

A ingestão via API exige armazenamento durável e compartilhado entre instâncias (o disco do Cloud Run é efêmero). A base atual tem 4 apostilas (257 páginas, ~195 mil caracteres).

## Decisões

1. **PostgreSQL + pgvector** com SQLAlchemy 2 assíncrono (`psycopg` 3) e migrations Alembic executadas por código (`python -m chatbot_api.db.migrate`, rodado no início do container). Um *advisory lock* serializa migrations concorrentes de várias instâncias.
2. **Esquema:** `documents` (hash SHA-256 único, status), `chunks` (texto, `page_start`/`page_end`) e `chunk_embeddings` com chave `(chunk_id, embedding_model)` e coluna `vector` **sem dimensão fixa** — dev (`bge-m3`, 1024) e prod (`cohere/embed-v4.0`, 1536) convivem sem migração.
3. **Sem índice HNSW por enquanto:** com ~150 trechos a busca exata (KNN completo) leva milissegundos e tem recall de 100%; o HNSW é aproximado e exigiria dimensão fixa (índice parcial por modelo). Reavaliar acima de ~50 mil trechos.
4. **Ingestão idempotente e retomável:** documento identificado pelo SHA-256 do arquivo; só trechos sem vetor para o modelo de embedding ativo são enviados ao provedor. Se o provedor falhar, o documento fica `failed` e a próxima execução retoma de onde parou. Trocar o modelo de embedding gera os vetores novos sem reprocessar o PDF.
5. **Chunking por frases** (~1500 caracteres ≈ 375 tokens, sobreposição de ~200 caracteres em frases inteiras), atravessando páginas e registrando o intervalo de páginas de cada trecho para citação. Medido na base: 151 trechos, média de 1405 caracteres.
6. **Normalização do texto extraído**, com regras medidas na própria base:
   - pypdf emite `\x00` no lugar das ligaduras "fi"/"fl" (402 ocorrências; ex.: `pro\x00ssionais`, `re\x00exão`). Regra: "fl" antes de `e/u/it/ag/or`, "fi" nos demais; `\x00` seguido de "fi"/"fl" é descartado (duplicação).
   - Um PDF perde o glifo por completo (`pro ssionais`): reparo específico.
   - Hifenização em fim de linha, espaços, caracteres de controle e composição Unicode (NFC).
7. **CLI** `uv run python -m chatbot_api.ingest docs/apostilas` reaproveitando o mesmo serviço que o upload via API (Fase 4) usará.

## Consequências

- Mudanças na normalização/chunking **não** reprocessam documentos já ingeridos (o hash é do PDF). Para aplicar, apague os documentos (`TRUNCATE documents CASCADE`) e reingira.
- Testes de integração exigem Postgres real (`TEST_DATABASE_URL`); a CI sobe um serviço pgvector.
- Bug encontrado na validação real e corrigido: reingerir documento sem trechos pendentes chamava o provedor com lista vazia e marcava o documento como `failed`.
